# DSH 原生更新器设计

## 目标

在 VectorAI 的 macOS DSH 启动器中提供轻量、可回滚的 DSH 更新能力，同时保持 DSH 源码与网页完全不受修改。

用户在 App 原生工具栏中看到当前 DSH 版本。官方同通道出现更高版本时，版本入口显示红点。用户点击入口可查看版本信息和官方原始更新说明或版本对比链接，并在确认后完成更新。

## 边界

- 更新功能全部位于 `apps/dsh-launcher-macos`。
- 不修改 DSH 源码、构建产物、网页 DOM 或插件协议。
- 不向 DSH 页面注入 JavaScript、CSS 或更新 UI。
- 不显示 VectorAI 插件版本或兼容状态。
- 不翻译更新日志；需要时直接打开官方页面。
- 不依赖 npm 发布状态。版本与源码均以 DeepSeek Harness 官方 Git tag 为准。

## 发布通道

更新器跟随当前运行版本的 SemVer 通道：

- 当前版本包含预发布标识时，只接受相同基础版本线或后续版本中的预发布与正式版本，并按 SemVer 排序选择最高版本。
- 当前版本为正式版本时，忽略预发布版本。
- 只接受格式为 `dsh-v<semver>` 的官方 tag。
- 无法解析的 tag、回退版本和相同版本均忽略。

## 原生界面

启动器为窗口增加 macOS 原生工具栏，在右侧提供版本入口：

- 无更新：显示当前版本，不显示红点。
- 有更新：版本入口右上角显示红点。
- 正在检查：不阻塞启动，不显示全局遮罩。
- 检查失败：保留当前版本显示，不弹出错误；用户点击入口时可看到“暂时无法检查更新”并手动重试。
- 正在更新：入口显示阶段与进度，现有 DSH 会话继续运行。

点击版本入口打开原生 popover 或 sheet，包含：

- 当前版本与目标版本；
- 官方 tag 页面与版本对比链接；
- “稍后”与“更新”按钮；
- 下载、安装或验证失败时的明确错误信息。

开始安装前使用原生确认对话框再次确认。更新完成并准备切换时提示应用将重启。

## 检查流程

App 启动并成功打开 DSH 页面后，在后台执行一次更新检查：

1. 请求 GitHub 官方仓库 tag 列表。
2. 过滤 `dsh-v*` tag，并依据当前通道选择最高版本。
3. 将结果缓存在 App 支持目录，记录检查时间、目标 tag、目标 commit 和官方链接。
4. 更新原生工具栏状态。

本版本不增加定时轮询。用户可从版本面板手动重新检查。

网络请求设置合理超时，并使用 GitHub API 响应中的 tag commit 作为安装身份。任何网络或解析错误都不得影响当前 DSH 启动与使用。

## 安装与切换

更新采用并行 runtime，而不是覆盖当前目录：

1. 在临时目录下载目标官方 tag 的源码。
2. 校验 tag 名、解析后的版本、commit 和源码内 CLI 版本一致。
3. 使用启动器已有的源码安装方式构建到新的版本目录。
4. 保持当前 DSH 服务运行，直到新 runtime 完整构建成功。
5. 写入原子化的 active-runtime 清单，记录新旧 runtime。
6. 停止当前 DSH 服务，使用新 runtime 启动。
7. 只有新服务通过就绪 URL 与插件树启动检查后，才将新 runtime 标记为稳定。

更新任务必须运行在后台队列，所有 UI 更新回到主线程。安装日志写入独立更新日志文件，不与 DSH 运行日志混写。

## 回滚与恢复

- 切换前保留上一个稳定 runtime。
- 新 runtime 无法启动、超时或插件树加载失败时，立即恢复 active-runtime 清单并启动旧 runtime。
- App 在启动时检测未完成的切换事务；若上次更新中断，则优先恢复最后一个稳定 runtime。
- 更新失败不删除下载或构建日志；临时源码可在失败后安全清理。
- 稳定启动后保留当前版本和前一个稳定版本，其余旧 runtime 可在后续版本中增加清理策略，本期不自动删除。

## 组件划分

### `UpdateChecker`

负责请求官方 tag、SemVer 与通道过滤、缓存检查结果。它不负责下载或切换 runtime。

### `RuntimeInstaller`

负责下载、校验和构建目标 runtime，并持续报告阶段与进度。它不停止当前服务。

### `RuntimeRegistry`

持久化当前、候选和最后稳定 runtime，使用临时文件加原子替换避免清单损坏。

### `UpdateCoordinator`

串联确认、安装、服务切换、健康检查和回滚，保证同一时间只有一个更新任务。

### `UpdateToolbarController`

管理原生工具栏版本入口、红点、版本面板和用户操作，不读取或修改 DSH 网页内容。

## 健康检查

新 runtime 的成功条件同时包括：

- DSH 进程在启动窗口内持续存活；
- 日志产生符合当前端口和 token 规则的就绪 URL；
- WebView 能完成本地主页面导航；
- 启动日志中不存在插件树加载失败。

只有全部满足才完成更新。健康检查失败时不向用户提供“继续使用损坏版本”的选项，直接回滚并报告原因。

## 安全要求

- 仅连接 `github.com` 与 GitHub API 的官方 DeepSeek Harness 仓库。
- 不执行远端提供的任意安装命令；构建步骤由 App 内固定实现定义。
- 所有下载与构建目标必须位于明确的临时目录或 VectorAI runtime 目录。
- 不覆盖 `~/.dsh`、模型凭据、会话或插件配置。
- 不在日志中写入 DSH ready URL 的 token、凭据或其他敏感参数。

## 验收标准

- 无新版时工具栏显示当前版本且无红点。
- 同通道有更高官方 tag 时显示红点。
- 正式版不会提示预发布版；预发布版遵循当前通道规则。
- 点击入口可查看版本信息、官方链接并手动重试检查。
- 取消确认不会下载、停止服务或改变 runtime。
- 更新构建期间当前 DSH 保持可用。
- 更新成功后 App 重启并运行目标版本。
- 下载、构建、启动或插件树检查失败时自动恢复旧版本。
- DSH 源码、网页 DOM 与插件代码不包含更新器实现或补丁。
