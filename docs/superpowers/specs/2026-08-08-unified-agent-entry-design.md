# VectorAI 统一 Agent 入口设计

> **部分废弃（2026-08-21）：** “无文字图片/PDF 默认重建图纸”的规则已取消。附件默认是普通参考上下文，只有显式 `drawing-source` 用途才进入导入/矢量化路径。

## 1. 目标

VectorAI 的 AI 对话区只提供一个业务入口。用户不需要理解或切换“普通模式”和“Agent 模式”；纯文字、图片、PDF，以及文字与附件的组合输入全部进入同一个 Agent Workflow。

Agent 接收请求后立即返回 `runId`，随后持续输出可审计的结构化进度。涉及图纸修改的任务必须先获得足以支撑修改的内部空间模型，再通过局部增量 Patch 完成修改，不能直接用一次视觉模型响应覆盖整张图纸。

## 2. 交互规则

- 移除 AI 面板中的“普通/Agent”切换开关。
- 纯文字、图片、PDF 和组合输入均调用 `startAgent()`。
- 没有文字的图片或 PDF 默认目标为“分析并重建二维工程图”。
- Agent 运行中提交纯文字时，文字作为追加指令进入当前运行，在下一个安全点生效。
- Agent 运行中不允许追加新附件，附件上传入口保持禁用；用户需先停止当前任务或等待其完成，再用附件启动新任务，避免并行运行隐式替换图纸上下文。
- 用户仍可在执行记录区域暂停、继续、停止任务，并观察增量提交。

## 3. 联合意图判断

每个新任务先经过轻量的 `InputIntent` 判断。判断输入包括用户文字、附件类型和低分辨率附件预览；输出是可审计的结构化分类，不包含模型隐藏推理。

```ts
type InputIntentKind =
  | 'create'
  | 'inspect_drawing'
  | 'reconstruct_drawing'
  | 'modify_drawing';

interface InputIntent {
  kind: InputIntentKind;
  summary: string;
  requiresDrawingPerception: boolean;
  requiresMutation: boolean;
  confidence: number;
}
```

意图判断只负责决定执行路径，不生成几何图元。首版使用以下确定性约束校正模型输出：

- 只要附件是图片或 PDF，且任务涉及修改，就必须先运行 Drawing Perception Pipeline。
- 仅附件且没有文字时，固定解释为 `reconstruct_drawing`。
- “分析、识别、检查”且没有修改要求时，可停在分析或重建结果，不额外生成修改步骤。
- “移动、删除、增加、替换、调整尺寸”等修改要求解释为 `modify_drawing`。
- 意图置信度低时仍继续执行安全路径：有附件先感知图纸，无附件按纯文字创建任务处理，并在审计事件中标记低置信度。

## 4. 动态执行计划

Agent Runtime 根据 `InputIntent` 生成最小执行计划：

| 输入与意图 | 执行阶段 |
| --- | --- |
| 纯文字创建 | 意图判断 → 规划 → 增量创建 → 验证 |
| 仅图片/PDF | 意图判断 → 图纸感知 → 内部模型重建 → 验证 |
| 图片/PDF + 仅分析文字 | 意图判断 → 图纸感知 → 输出分析/重建结果 |
| 图片/PDF + 修改文字 | 意图判断 → 图纸感知 → 基准模型重建 → 规划修改 → 增量修改 → 验证 |

图纸感知继续使用现有的页级分析、视图拆分、区域识别、拼接、拓扑与尺寸关联管线。基准模型的 Patch 提交完成后，修改规划器读取当前 `SpatialModel` 和原始用户指令，生成后续修改步骤。每个阶段和 Patch 都沿用同一个 `runId`，从而支持完整审计和确定性回放。

## 5. 进度与性能

- HTTP 启动请求只负责校验、保存附件和创建运行记录，应尽快返回 `runId`。
- 意图判断开始、完成、图纸感知开始、每个视图或区域完成、Patch 提交、修改规划与验证均产生结构化事件。
- 长模型调用期间继续使用不超过 25 秒的 heartbeat，保证 UI 在 30 秒内至少收到一次回执。
- 意图判断默认使用 `doubao-seed-2.0-lite`；它只做小型结构化分类，不承担完整图纸重建。
- 低置信度的几何结果按现有规则标红。意图判断本身不因低置信度自动升级 Turbo，以免增加首个回执延迟；只有后续几何结果满足既定升级条件时才使用 `doubao-seed-2.1-turbo`。

## 6. 错误处理与审计

- 意图判断失败时记录错误并执行确定性回退，不让任务直接失败。
- 图纸感知的局部区域失败沿用隔离策略：记录 `perception-error`，保留其他区域已完成的提交。
- 基准模型重建失败时不得继续执行依赖该模型的修改步骤，任务以明确的阶段错误结束。
- 修改失败不回滚已经提交的基准模型；用户可以查看、撤销或基于当前模型继续下达指令。
- 审计记录至少包含输入类型、意图分类、分类置信度、采用的执行路径、阶段耗时、模型角色、Patch/Commit 标识和终止原因，不保存原始媒体或隐藏推理。

## 7. 代码边界

- `AIDialog` 只负责收集输入、展示附件和调用统一的 Store 行为，不再包含模式路由。
- Store 将新任务统一投递给 `AgentClient.start()`；运行中纯文字统一调用 `addInstruction()`。
- Agent Runtime 拥有 `InputIntent` 判断、执行路径选择和阶段编排。
- Drawing Perception Pipeline 只负责将图纸转换为内部观察结果和基准 Patch，不解释修改指令。
- Planner/Executor 只在需要创建或修改时处理当前 `SpatialModel`，不重复进行整图视觉识别。
- 旧 `/api/ai/generate` 和 `/api/ai/perceive` 可暂时保留为内部兼容接口，但 UI 不再直接调用；后续在调用方清零后单独移除。

## 8. 测试与验收

自动化测试必须覆盖：

- AI 面板不存在模式切换，发送文字、图片、PDF 或组合输入都调用统一 Agent 入口。
- 运行中纯文字进入追加指令，不启动第二个运行。
- 运行中不能上传附件或隐式启动第二个运行。
- 仅附件获得默认重建目标。
- 组合输入能够区分仅分析与分析后修改。
- 修改图纸的执行顺序固定为先感知和重建基准模型，再提交修改 Patch。
- 意图判断失败时执行确定性回退并留下审计事件。
- 每个阶段共享 `runId`，回放能恢复相同的提交序列和最终模型。
- 启动接口及时返回，长步骤持续发送 heartbeat。

验收时使用 `test1.jpg` 验证真实流程：上传图片并输入修改要求后，执行记录应先显示意图判断和图纸重建，再显示修改规划与增量修改；界面不得出现“普通/Agent”切换，也不得请求旧 `/api/ai/perceive` 路径。
