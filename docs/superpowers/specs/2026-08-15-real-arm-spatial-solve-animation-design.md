# 真实手臂空间求解动画改造设计

## 目标

将 `vectorai-model-program-roles` 动画中“确定性空间求解”场景的抽象三段式手臂，替换为 VectorAI 当前 `test2` 空间编辑链路使用的真实右臂数据。观众应能直观看到：程序识别真实图元、锁定肩部边界锚点、围绕锚点计算变换，并在保持连接关系的前提下生成可编辑结果。

## 已核实的数据来源

- 输入图像：项目根目录 `test2.png`。
- 原始共享折线：`TEST2_SHARED_POLYLINE_POINTS`。
- 右手轮廓：`node_test2_hand_outline`。
- 肩部边界锚点：`[118.992468, 203.546338]`。
- 实际空间变换：围绕肩部锚点旋转 `35°`。
- 真实预览结果：`.local/vectorai/baselines/test2-region-edit/final-preview.png`。

## 方案比较

1. **角色轮廓上下文 + 真实图元高亮（采用）**：淡化显示角色局部轮廓，高亮右臂真实折线、轮廓和肩部锚点。信息最容易被非技术观众理解，同时保留工程可信度。
2. **仅展示真实图元**：数据最纯粹，但观众不容易立即判断图元对应人物的哪一部分。
3. **直接叠加原始位图**：最接近素材来源，但白底和复杂线稿会削弱透明覆盖动画的可用性。

## 画面设计

只修改现有动画的“确定性空间求解”面板，保持整体时长、旁白节奏、透明背景和其他场景不变。

- 面板左侧淡化绘制哆啦 A 梦的头部、躯干和双臂轮廓，作为空间上下文。
- 右臂使用真实 `test2` 折线点构造，目标轮廓以蓝灰色高亮。
- 肩点显示为锁定锚点，并标注真实坐标 `A (118.992468, 203.546338)`。
- 求解阶段显示旋转弧、`θ = 35°`、图元 ID 和连接状态。
- 动画以肩点为旋转中心，将右臂从原始位置旋转到真实求解结果；肩点保持不动。
- 结束时显示 `ANCHOR LOCKED`、`TOPOLOGY PRESERVED` 和 `PREVIEW VALID`，强调这是确定性执行结果。

## 数据与动画映射

HTML 中保存一份来自 `test2-fixture.ts` 的显式坐标常量，并按 SVG 视口进行统一缩放和平移。旋转结果不凭视觉手调，而是使用同一个肩点和 `35°` 变换公式计算。角色上下文只承担识别作用，不参与空间求解动画。

## 验证标准

- 原始右臂点、肩点和角度与项目 fixture 一致。
- 旋转前后肩点像素位置不发生漂移。
- 右臂与肩部保持连接，画面中不出现断点。
- HyperFrames lint 和关键时间点 inspect 无错误、溢出或遮挡。
- 重新导出透明 WebM 与 ProRes 4444 MOV，并用彩色背景合成验证 Alpha。

## 范围限制

- 不更改项目的空间求解实现或 fixture。
- 不修改其余三个动画场景。
- 不把 `test2.png` 的白色背景直接嵌入透明成片。
