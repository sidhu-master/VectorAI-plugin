# 深色 CAD 工作区与 Agent 任务面板设计

## 目标

在不改变现有 Agent 业务流程的前提下，将网站统一为克制、专业的深色 CAD 工作区；把任务执行过程整理为用户可理解、可暂停、可追加指令的阶段式交互；同时修复显式 CAD 图元导致画布崩溃、整页消失的问题。

本轮采用“ChatGPT 的克制感 + CAD 工作区密度”方案。模型名、角色名、尝试次数和原始运行 ID 不出现在普通任务界面，但完整数据继续写入本地审计记录，供调试与回归使用。

## 视觉系统

- 使用接近黑色的中性灰作为画布背景，侧栏与工具栏只通过一到两级明度和细边框区分层级，不使用大面积蓝紫色背景。
- 全站仅使用一个低饱和蓝青色作为选中、发送、当前步骤和主操作强调色。
- 绿色、橙色和红色只用于完成、警告和失败等小面积语义状态；普通进度不使用彩虹式颜色。
- 正文与控件使用无衬线字体；坐标、尺寸和内部标识使用等宽字体。
- 统一按钮高度、圆角、间距、悬停、按下、禁用和焦点状态，减少当前页面中零散的视觉规则。
- 画布保持最深，左右面板略亮；主几何使用浅灰线，选中图元使用强调色，低置信度图元使用红色，构造线使用弱化虚线，尺寸与文字使用次级浅灰。

## 页面布局

- 顶部工具栏保持紧凑，承载文件、视图和主要操作，不堆放运行状态。
- 左侧属性区保留对象列表、感知信息和参数编辑，但统一为可扫描的区块标题、字段和空状态。
- 中央画布是视觉主体，获得最大空间；缩放、平移和选择反馈遵循 CAD 编辑器习惯。
- 右侧 AI 区由对话、任务卡和固定底部输入框组成。输入框是普通请求和运行中追加指令的唯一入口。
- 底部状态栏只展示坐标、缩放、实体数量和连接状态等短信息。
- 第一版以桌面工作区为主；窄屏时侧栏允许收起，但不为移动端重新设计完整 CAD 操作流。

## Agent 任务面板

### 用户可见内容

任务卡顶部显示自然语言状态，例如“正在解析图纸”和简短的运行时长。流程固定映射为五个用户阶段：

1. 理解需求
2. 解析图纸
3. 构建模型
4. 应用修改
5. 验证完成

当前阶段使用单一强调色和轻量活动指示；完成阶段使用中性勾选；未开始阶段降级显示。任务完成后收拢为结果摘要，例如“已完成 12 次增量修改 · 用时 42 秒”。

工具调用、心跳、重试和阶段耗时放入默认折叠的“执行详情”。这里使用经过整理的用户文案，不展示模型名、模型角色、原始运行 ID、调用参数或底层异常堆栈。

### 交互

- 运行中提供“暂停”和“停止”；暂停后提供“继续”。
- 用户在主输入框追加文字或图片时，沿用现有统一意图分析入口，将内容加入当前运行，而不是在任务卡内设置第二套输入框。
- 失败状态在任务卡内显示简短原因和重试操作；可诊断详情写入审计记录。
- 任务卡只负责展示与控制，不负责决定模型路由；低置信度升级模型仍由服务端策略处理。

### 审计边界

用户界面隐藏模型元数据不等于删除它。运行事件、模型路由、工具调用、输入输出摘要、持续时间、提交记录和错误信息继续保存到本地审计文件，确保流程可审计、可回放和可回归。后续如需调试界面，应作为明确的开发者入口，而不是混入普通任务面板。

## CAD 画布架构

当前崩溃的根因是画布边界计算和渲染只覆盖点、直线、圆，而模型已能输出圆弧、椭圆、构造线和尺寸等显式 CAD 图元。边界函数返回空值后仍被直接读取，导致 `Canvas` 抛错并使整页卸载。

本轮将画布职责拆为三个可独立测试的单元：

- `entityBounds(entity)`：穷举点、直线、射线、构造线、圆、圆弧、椭圆、多段线、样条曲线、文字和尺寸，返回有限边界或 `null`。无限图元根据当前视口裁剪，不参与无界自动缩放。
- `EntityRenderer`：按显式图元类型生成 SVG 元素；图元的颜色只由统一样式状态决定，不在每种图元内自定义一套颜色。
- `Canvas`：负责视口、缩放、平移、选择和组合渲染；自动取景仅合并有效且有限的边界。

圆弧边界需要包含起止点以及落在弧段内的象限极值；旋转椭圆边界按旋转后的轴向极值计算。多段线按顶点与闭合状态渲染。第一版样条曲线使用已有控制点生成平滑 SVG 路径。射线和构造线裁剪到可视区域。文字与尺寸先提供稳定、可读的二维显示，不实现高级标注样式、图层、图块和填充。

## 数据流

后端事件仍作为唯一运行事实来源。前端将底层事件先映射为标准任务阶段与用户文案，再交给任务卡渲染；原始事件不直接拼接到界面。模型输出的实体先通过运行时校验进入内部空间模型，画布再根据实体联合类型调用边界与渲染单元。

正常流程为：用户输入 → 意图分析 → 可选图纸解析 → 空间模型增量提交 → 前端事件阶段映射 → 画布渲染。运行中追加指令进入同一运行队列，并保留独立审计事件。

## 错误处理

- 单个非法或尚未支持的图元返回 `null` 边界并跳过渲染，同时记录可审计警告，不得让整个画布崩溃。
- `Canvas` 外增加组件级错误边界。不可预期错误只替换中央画布为恢复提示，左右面板、任务状态和输入框继续工作。
- 错误边界提供“重新加载画布”操作；不会隐式删除当前模型或运行记录。
- 任务失败与渲染失败分开表示。任务已完成但前端无法显示时，不得误报为 Agent 任务失败。
- 自动取景忽略非有限数值、空边界和无限构造图元，避免 `NaN` 或无穷坐标污染视口。

## 测试与验收

- 为每一种显式二维图元增加边界单元测试，覆盖空数据、旋转椭圆、跨越零度的圆弧和无限图元。
- 为每一种图元增加渲染测试，确认生成稳定 SVG 且不抛异常。
- 增加包含圆弧、椭圆、构造线和尺寸的合成回归模型，复现并锁定本次整页消失问题；测试夹具不依赖未跟踪的 `test1.jpg`。
- 增加任务面板测试，确认模型名和底层元数据不会出现在 DOM 中，阶段映射、折叠详情、暂停/继续和失败态正确。
- 增加错误边界测试，确认画布异常时任务面板和输入框仍然存在。
- 运行现有全量测试、类型检查和生产构建；最后在本地浏览器以真实任务记录验证布局、任务状态、所有返回图元和窄窗口侧栏行为。

## 非目标

- 不增加图层、图块、填充和三维能力。
- 不引入新的后端持久化服务，审计继续存本地。
- 不向用户暴露模型切换开关或模型名称。
- 不在本轮实现完整移动端 CAD 编辑体验。
- 不改变低置信度模型升级策略和现有增量提交语义。

## 完成标准

使用最近一次包含圆弧、椭圆、构造线和尺寸的模型打开页面时，画布可见且整页不崩溃；任务面板不出现任何模型名称，执行过程可暂停、继续并通过主输入框追加指令；全站呈现统一的中性深色 CAD 视觉，低置信度实体仍清晰标红；全量自动化验证通过，原始审计数据保持完整。
