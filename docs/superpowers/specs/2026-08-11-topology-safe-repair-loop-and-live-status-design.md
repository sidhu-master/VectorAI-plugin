# 拓扑安全的空间编辑修复 Loop 与真实任务状态设计

**日期：** 2026-08-11

**状态：** 已确认设计方向，待进入实现计划

**适用范围：** Region-First 二维空间编辑、Drawing IR 增量事务、任务进度 UI

## 1. 背景与问题

真实测试指令“把图形的右手抬起来打招呼”已经正确进入 Region-First 流程，也生成了局部候选事务，但候选未能通过确定性校验，随后运行失败。

本次运行暴露出五类结构性问题：

1. 当前编译器给拆分后的保护片段附加了设计质量元数据，导致本应保持不变的保护片段哈希发生变化，触发 `PROTECTED_FRAGMENT_CHANGED`。
2. 模型对同时存在多个连接锚点的手臂使用单一刚体旋转。除恒等变换外，一个刚体变换无法同时固定多个独立锚点，因此产生 `BOUNDARY_ANCHOR_DISCONNECTED` 和新的悬空端点。
3. 区域切分在图元端点附近产生极短片段。这些片段不是有意义的语义边界，却被当作连接锚点，放大了拓扑错误。
4. 策略路由使用整张图上的尺寸标注判断“工程几何”。测试图包含自动标注，因此局部的自由曲线手臂被错误地强制走解析几何路径。
5. 候选失败后，运行时重新进行区域识别，而不是复用已经正确的区域、选区和切分结果，仅修复失败的设计。这增加了延迟、成本和不确定性。

前端同时存在表现层问题：后端已经发布真实的区域识别、切分、设计、预览、验证和修复事件，但任务卡片把这些事件投影成固定的五个阶段，用户看不到真实过程；通用模型事件和心跳还会覆盖更有价值的业务状态。

## 2. 目标

本次设计要实现以下结果：

- 用户只需描述意图，不必反复补充“保持连接、其他部分不变”。
- AI 仍拥有对图纸的完整控制能力，但所有修改必须通过 Drawing IR 增量事务落地。
- 局部修改默认保护未选区域和已有连接拓扑。
- 候选失败后形成真实的观察—验证—反馈—修复 Loop，而不是重新开始整条流程。
- 第 1、2 个逻辑候选均使用轻量模型；仅第 3 个逻辑候选升级到高能力模型。
- 用户在画布上看到候选逐步出现、失败原因和修复过程；最终失败时不残留错误候选。
- 任务面板只显示当前最新的真实状态，但完整事件仍进入审计记录和回归数据。

## 3. 非目标

- 本次不引入完整的 CAD 参数约束求解器。
- 本次不要求任意自由曲线都重新提升为圆、圆弧或样条等高级解析图元。
- 本次不改变 Drawing IR 作为前后端、审计、回放和渲染的唯一规范数据源。
- 本次不依靠单纯升级模型或扩充提示词掩盖确定性几何问题。
- 本次不把内部模型名称显示给最终用户。

## 4. 系统级默认语义

对所有局部空间编辑，运行时自动附加以下不变量。它们属于执行协议，不依赖用户是否在提示词中说出：

1. **区域外不变：** 未被目标区域覆盖的图元和图元片段必须保持字节级或规范化语义级一致。
2. **保护片段不变：** 因区域切分产生的保护片段不得附加设计元数据、移动、重采样或改变样式。
3. **连接拓扑保持：** 编辑前跨越目标边界的有效连接，在编辑后仍应连接到同一保护侧语义位置。
4. **不新增悬空端点：** 仅拒绝候选新引入的悬空端点；原图已有的矢量化缺陷不应被误判为本次编辑造成。
5. **最小影响范围：** 在满足用户意图的候选中，优先修改更少的节点、更小的包围盒和更短的总曲线长度。
6. **原有样式保持：** 除非用户明确要求，线宽、颜色、虚实、标注和相邻图元均保持不变。

这些不变量会同时进入设计上下文、确定性编译器、验证器和审计记录。模型可以提出修改方案，但不能绕过验证器直接提交。

## 5. 拓扑感知的区域解析

### 5.1 目标局部化

策略判断只使用目标区域及其一阶拓扑邻域，不再用整张图是否存在尺寸标注来决定局部编辑模式。自动标注只作为显示和校验信息，不得把卡通或自由曲线目标错误分类为硬工程几何。

局部特征包括：

- 目标内部解析图元和自由曲线的比例；
- 与目标边界相交的曲线数量；
- 独立连接锚点数量和几何分布；
- 目标是否包含工程尺寸、正交、同心、相切等局部约束；
- 用户意图是刚体移动、形变还是新增外观。

### 5.2 端点吸附与短片段清理

切分参数接近 `0` 或 `1` 时，不创建无意义的极短片段，而是吸附到原图元端点。阈值由 Drawing IR 几何容差和图元长度共同决定：

```text
snapDistance = max(documentTolerance × K1, entityLength × K2)
```

其中 `K1`、`K2` 是可测试的保守常量。清理步骤必须在建立边界锚点之前完成，并记录吸附决策，保证回放确定性。

满足以下任一条件的短片段应合并回相邻片段或取消本次切分：

- 几何长度低于 `snapDistance`；
- 参数区间低于相对阈值；
- 片段没有独立语义、交点或样式变化。

### 5.3 有效连接锚点

边界相交点不自动等于需要保持的连接锚点。只有编辑目标与保护区域之间真实的拓扑连接才成为约束锚点。

锚点记录至少包含：

- 稳定锚点 ID；
- 原节点 ID 与 lineage；
- 保护侧和目标侧片段 ID；
- Drawing IR 坐标；
- 切向方向；
- 容差；
- 编辑前连接关系。

## 6. 编辑策略路由

路由器根据目标局部特征选择三条路径。

### 6.1 解析/刚体编辑

适用于工程图元、单锚点部件，或能够在不破坏全部锚点的情况下完成的平移、旋转、缩放。模型输出意图参数，确定性编译器生成 Drawing IR 命令。

在执行前先做可行性检查：如果一个非恒等刚体变换需要同时固定两个及以上不共变的独立锚点，则该方案不可行，必须转入锚定形变或局部重绘。

### 6.2 锚定形变

适用于手臂、轮廓、软管等自由曲线区域：局部形状需要变化，但与身体、设备或边界的连接必须保留。

模型不直接枚举低层点坐标，而是输出高层设计参数：

- 固定锚点集合；
- 运动支点或控制区；
- 目标方向、角度或末端位置；
- 允许变形的子区域；
- 必须保持的对称、光顺或长度偏好。

确定性编译器把目标曲线采样到局部形变域，使用带固定边界条件的平滑形变计算新几何。固定锚点必须精确回落到原坐标，锚点附近切向尽量连续。

自由曲线可以在候选阶段暂时降级为 polyline 或 spline，以保证表达完整；后续的图元提升流程再尝试拟合为圆弧或其他解析图元。工程解析图元不应未经授权降级，应继续走解析/约束路径。

### 6.3 局部重绘再矢量化

适用于增加发型、装饰或复杂外观等生成式意图。系统在带保护遮罩的局部栅格中重绘，再矢量化为 Drawing IR 候选，并通过同一拓扑和差异验证。

此路径仍然必须使用原连接锚点与保护遮罩，不能成为绕过 Drawing IR 事务和确定性校验的旁路。

## 7. 失败分类与修复 Loop

每次候选验证失败后，先分类，再决定复用哪些上下文。

| 失败类型 | 典型问题 | 下一轮动作 | 是否重新区域识别 |
| --- | --- | --- | --- |
| 协议/格式 | JSON、schema、工具参数格式错误 | 同一次模型调用内纠正协议 | 否 |
| 设计/拓扑 | 锚点断开、新增悬空端点、形变不可行 | 保留观察、区域、选区、切分和锚点，反馈缺陷并重新设计 | 否 |
| 候选编译 | 受保护片段变化、非法命令、lineage 错误 | 修复确定性编译或要求替代设计 | 否 |
| 选择错误 | 选错部件、目标为空、关键连接不在选区 | 使用失败证据重新区域识别 | 是 |
| 输入过期 | 用户追加指令、Drawing IR revision 已变化 | 基于最新 revision 重新规划 | 是 |
| 提供方故障 | 超时、限流、服务不可用 | 在同一上下文内按运行策略重试或明确失败 | 否 |

设计/拓扑失败不得再次调用完整区域识别。下一轮模型收到紧凑但完整的 Episode 上下文：原始意图、区域、选中节点、保护片段、锚点、上轮设计、候选预览摘要、验证错误和可行策略建议。

### 7.1 三轮模型升级规则

模型升级按“逻辑候选轮次”计数，不按底层 API 请求次数计数：

| 逻辑候选轮次 | 模型等级 | 上下文 |
| --- | --- | --- |
| 第 1 轮 | Lite | 用户意图、局部视觉、Drawing IR、拓扑约束 |
| 第 2 轮 | Lite | 第 1 轮全部上下文，加候选差异和验证失败证据 |
| 第 3 轮 | Turbo | 完整紧凑 Episode，加前两轮失败轨迹和可行性提示 |

具体约束：

- schema 修复、JSON 纠错和单次调用内部的工具参数纠正不消耗逻辑候选轮次。
- 第 2 轮即使失败原因明显，也仍使用 Lite。
- 只有准备生成第 3 个候选时才升级到 Turbo。
- 第 2 轮发现目标选择本身错误时，第 3 轮可以使用 Turbo 重新区域识别；否则第 3 轮继续复用已有区域。
- 最多生成 3 个逻辑候选。第 3 轮仍失败则保留原图并向用户报告准确原因，不自动提交错误结果。
- 模型名称只进入审计数据，不显示在任务面板。

## 8. 候选预览与提交语义

候选是临时覆盖层，不是规范 Drawing IR 状态。

1. 新候选产生后立即显示，用户可以看到实际变化。
2. 验证中的候选使用统一的候选样式；验证失败时短暂标红或使用虚线，并显示精确缺陷，例如“手臂与身体的 2 个连接点断开，正在修复”。
3. 下一候选到达时原子替换上一候选，禁止多个失败候选叠加。
4. 只有通过确定性验证的候选才允许提交为 Drawing IR 增量事务。
5. 第 3 轮失败、取消或终止时，移除临时候选，画布恢复到规范原图；错误候选只保留在审计快照中。
6. 用户暂停时保留当前可解释状态，但不得把未验证候选当作已提交内容。

## 9. 差分验证

验证器从“检查候选是否完美”调整为“检查候选是否违反本次事务约束”。

### 9.1 保护区域

- 保护片段在切分完成后立刻生成基线哈希。
- 设计质量和置信度元数据只能写入目标片段或事务记录，不得写入保护片段。
- 验证时使用规范化几何、样式、语义和 lineage 比较，忽略不属于节点内容的运行时字段。

### 9.2 连接拓扑

- 每个有效锚点都必须在候选中找到目标侧连接。
- 连接位置在容差内一致；需要光顺时同时校验切向偏差。
- 解析几何路径还应校验原有局部工程约束。

### 9.3 悬空端点差分

先分别计算基线和候选的目标邻域悬空端点集合，只拒绝候选新增的悬空端点。这样可以防止 test2 矢量化原本存在的细小缺陷阻止任何后续编辑。

## 10. 最新真实任务状态 UI

主任务卡片不再显示固定阶段列表，也不在主视图累计所有事件，只显示最新一条有业务意义的真实状态。

建议呈现：

```text
正在修复手臂与身体的连接
第 2/3 次尝试 · 已用时 42 秒
```

状态来源优先级：

1. 领域事件：区域识别、选择解析、边界切分、策略选择、候选生成、预览、验证、修复、提交。
2. 用户控制事件：暂停中、已收到追加指令、正在基于新指令重规划。
3. 提供方事件：等待模型、超时重试；仅在没有更准确的领域动作时显示。
4. 心跳：只更新“仍在处理”和已用时，不得覆盖当前领域动作。

UI 行为：

- 使用本地每秒计时器更新已用时，不依赖后端高频推送。
- `model_started`、`model_finished` 等通用事件默认不覆盖最近的领域状态。
- 同一状态长时间运行时，保留动作文本并更新已用时；超过提示阈值后附加“这一步需要更长时间”。
- 显示逻辑候选轮次，但不显示模型名称。
- 失败时显示经过安全处理的准确业务错误，不再只显示“请稍后重试”。
- 暂停、继续、追加指令和取消控件继续保留。

完整事件历史不删除。它仍写入 Episode、审计链和回放文件，只是不在主任务卡片中展开。调试模式可以查看完整时间线和原始事件。

### 10.1 超时与临时失败重试

超时、网络中断、限流和模型服务临时不可用进入可重试终态。任务卡显示准确错误和“重试”按钮。

点击重试时：

- 使用原始用户目标和原始附件；
- 读取当前规范 Drawing IR 的最新 revision；
- 创建全新的 runId 和审计 Episode，不复活失败运行；
- 清除失败运行的临时候选、区域覆盖层和隐藏节点；
- 保留已经成功提交到 Drawing IR 的事务；
- 不在对话中重复插入同一条用户消息；
- 新运行的逻辑候选轮次从第 1 轮重新开始。

非临时的确定性失败仍可保留重试入口，但必须先显示具体失败原因，避免让用户误以为重试必然改变结果。重试过程本身也显示最新真实状态。

## 11. 状态与审计数据

每个候选轮次至少记录：

- `candidateAttempt`：1、2 或 3；
- `modelTier`：仅审计使用；
- `reusedContext`：区域、选区、切分、锚点的 revision/ID；
- `strategy`：解析、锚定形变或局部重绘；
- `candidateTransaction` 与预览快照；
- `validationIssues`；
- `repairClassification`；
- `durationMs` 与模型调用次数；
- 最终提交、失败、暂停或取消状态。

所有候选都必须可离线回放。回归测试可以固定 Drawing IR、区域和模型结构化输出，重跑编译与验证，无需重复调用外部模型。

## 12. 测试与发布门槛

### 12.1 单元测试

- 保护片段不再被 `withDesignQuality` 修改。
- 端点附近的切分被吸附，不产生极短片段和伪锚点。
- 多锚点刚体变换在编译前被判定不可行并路由到锚定形变。
- 悬空端点按基线差分，只拒绝新增项。
- 局部策略不受区域外自动尺寸标注影响。
- 失败分类正确决定复用或重新识别。
- 第 1、2 个逻辑候选使用 Lite，第 3 个使用 Turbo；schema 纠错不增加轮次。
- 终止失败会清除临时候选并恢复规范 Drawing IR。
- 任务卡片只显示最新真实状态，通用模型事件和心跳不会覆盖领域状态。
- 重试使用当前 Drawing IR revision 创建新运行，复用原始输入且不重复添加用户消息。

### 12.2 集成测试

- 固定一个包含多个连接锚点和端点短片段的手臂区域，验证候选能保持连接、区域外不变并通过事务校验。
- 验证设计失败后不会重新调用区域识别，而是复用 region/selection/split/anchors。
- 验证选择失败时才重新进行区域识别。
- 验证失败候选显示、标红、替换、清理的完整前后端事件序列。
- 验证任务暂停和追加指令时，候选与规范 Drawing IR 状态不混淆。
- 验证超时终态可重试，新旧 runId、Episode 和候选轮次相互独立。

### 12.3 真实验收

以 test2 当前 Drawing IR 为基线，用户只输入：

> 把图形的右手抬起来打招呼

无需补充“保持手臂与身体连接，其他部分完全不变”，最终结果也必须满足：

- 右手呈抬起打招呼的可辨识姿态；
- 手臂与身体原有连接保持闭合；
- 其他部位没有可见变化；
- 用户能看到候选、验证和必要的修复过程；
- 任务卡片显示真实的当前动作和逻辑候选轮次；
- 成功后只有一个通过验证的增量事务进入 Drawing IR；
- 失败时画布恢复原图，并给出准确、可行动的原因。
- 超时后可以从任务卡直接重试，且已提交修改不会丢失。

## 13. 实施边界

实施按以下依赖顺序进行：

1. 修复保护片段污染、端点短片段和差分验证等确定性基础。
2. 建立失败分类、上下文复用和三轮模型升级状态机。
3. 增加刚体可行性判断与锚定形变编译路径。
4. 完成候选覆盖层的失败标记、原子替换和终止清理。
5. 把任务面板切换为最新真实领域状态。
6. 以自动化回归和 test2 真实流程共同验收。

该顺序保证每一层都有可测试的输入输出，也避免模型行为掩盖编译器和验证器的确定性错误。
