# 纯图片快速矢量化与逐线呈现设计

**日期：** 2026-08-14  
**状态：** 已废弃（2026-08-21）

> 本设计中的“纯图片自动矢量化”已被撤销。附件默认是普通参考上下文；只有结构化用途明确为 `drawing-source` 或用户显式调用图纸导入时才允许矢量化。本文仅保留为历史记录。

## 目标

当用户只上传一张图片且没有输入文字时，VectorAI 不应先调用模型来选择一个确定性的
`vectorize_image` 工具。系统应立即开始本地矢量化、分批预览、原子提交和自动标注，
同时在画布上把每批图元呈现为连续的逐线绘制过程。

最近一次真实运行中，首轮模型请求耗时 32.7 秒、请求体 5.44MB，而模型只返回了
`vectorize_image`；真正矢量化耗时 3.6 秒。因此首轮模型是主要延迟来源。

## 路由边界

- `image/*` 附件且用户文字为空：走确定性图片导入快路。
- 图片附带任何用户文字：保持 Agent 路径，由模型理解“分析、重建或修改”的意图。
- PDF：保持现有 Agent 路径，本轮不改变。
- 前端不再把内部默认语句“解析并重建上传的二维图纸”作为纯图片请求的 `goal` 发送；
  空 `goal` 与图片附件共同构成明确、可审计的快路信号。
- 用户在导入中追加文字时，系统先完成可编辑 Drawing IR 的建立，再在同一 Run 中切回
  Agent 处理追加指令。

## 确定性导入流程

1. Run 接收后立即发布“正在读取图片并提取线稿”。
2. Runtime 直接调用 `vectorize_image`，不构造模型上下文、不上传图片给模型。
3. 按候选清单的 `batchIndex` 顺序调用 `preview_vectorization_batch`。
4. 每批沿用现有局部几何校验、Preview、Drawing IR 事务和原子 Commit。
5. 所有批次完成后调用现有自动标注生成与提交。
6. 没有追加指令时直接完成；存在追加指令时进入正常模型循环。

暂停、停止、审计、提交与回放仍使用同一个 Agent Run。确定性动作进入审计，但不得伪装成
模型动作。任一工具失败时返回真实错误，不回退到一次大图模型调用。

## 逐线动画

服务端仍以最多 48 个图元的批次发送一次 `PerceptionPreviewDelta`，不为每个图元制造 SSE
事件。前端在批次内按稳定顺序计算 0–220ms 的延迟；每条 SVG 路径用归一化
`pathLength=1` 在约 300ms 内从起点描到终点。整批动画控制在现有 520ms Preview
停留窗口内，因此不阻塞后端矢量化或提交。

- 直线、圆、圆弧、椭圆、Polyline 和 Spline 使用路径描绘。
- 标注和文字沿用短暂淡入。
- 预览色使用现有克制的浅蓝色；低置信度图元仍保持红色。
- 不使用昂贵 SVG 模糊滤镜，拖动和缩放期间不增加 React 状态更新。
- `prefers-reduced-motion: reduce` 时立即显示最终线条，仅保留数据进度。
- 动画只用于 `outline` 矢量化预览，普通编辑和已提交图元不会反复播放。

## 验收

- 纯 PNG/JPEG/WebP 且无文字的 Run 完成矢量批次和自动标注，模型调用次数为 0。
- 首个 `vectorizing` 状态在模型网络往返之前出现，且审计中没有 `model_call`。
- 图片加文字和 PDF 的既有 Agent 行为不变。
- 每批 Outline 路径具有有界延迟和逐线描绘属性，最后一条在 520ms 内完成。
- 减少动态效果时动画被禁用。
- 类型检查、Lint、生产构建和全量回归测试通过。
