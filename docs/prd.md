# VectorAI 产品需求文档

> 产品阶段：插件平台化与第二层专业工作流
>
> 更新日期：2026-08-24

## 1. 产品愿景

VectorAI 让 AI 与用户共同操作真实、可查询、可撤销的二维空间，而不是让模型生成一张不可编辑的结果图。用户在 DSH 对话中表达目标，模型负责语义判断，确定性算法负责图元选择后的精确坐标、约束与事务计算，用户通过统一画布查看和直接调整结果。

产品本地优先、代码开源，不依赖 VectorAI 云端、Express 服务或远程状态。宿主可以是 DSH、VectorAI 自己的网站或未来其他应用，只需实现不同 Adapter。

## 2. 两层插件模型

### 第一层：2D Space

第一层是通用二维能力和唯一图纸权威，负责：

- Canonical Drawing 文档、revision、查询、Preview、Commit、Undo/Redo；
- 图纸导入与本地矢量化，但只在用户或工具显式调用导入能力时执行；
- 网格、坐标轴、图元、关系、标注、对象和属性等基础画布；
- 用户选择、模型注意状态、临时约束和 Preview 的分离展示；
- 语义选取、确定性几何求解、诊断与 auto-safe/确认策略；
- DSH Host/Client、本地持久化和宿主资源生命周期。

普通图片附件只是对话上下文。上传、粘贴、存在图片或打开新会话都不得自动创建 Drawing、自动矢量化或打开画布。

### 第二层：Engineering Annotation

第二层是独立安装、独立发布的专业插件，基于第一层公共协议实现：

- 工程特征识别、分区、尺寸候选和关联；
- 标注布局、碰撞处理、覆盖率和冲突检查；
- 专业工作流状态与完整专用 UI；
- 通过第一层 Preview、评估和 Commit 写入正式标注。

第二层不拥有另一份 Drawing、不直接写本地文件、不启动聊天或服务端，也不绕开第一层事务权限。

两个插件暂时放在同一 monorepo，以便原子升级公共协议；它们仍是独立包和独立能力边界。

## 3. 核心用户流程

### 查看与手动编辑

1. 用户显式导入图纸或打开已有会话 Drawing。
2. 第一层在 DSH 对话同页显示二维画布。
3. 用户可拖动/缩放、框选/点选、查看对象和属性、提交属性修改、撤销/重做与导出 DXF。
4. 点击画布空白取消选择；交互语义在网站和 DSH 中一致。

### AI 语义编辑

1. 用户针对已有 Drawing 发出自然语言目标。
2. DSH 按需激活绘图工具，不在全局提示中注入固定工作流。
3. 模型观察并用语义引用选取部件；画布仅将真实目标显示为 AI 注意状态。
4. Host 把已验证范围编译为确定性 Preview；模型不手算世界坐标。
5. 诊断和独立评估产生 `blocked | confirmation_required | auto_safe`。
6. auto-safe 可自动提交；需确认的 Preview 等待用户；正式修改生成新 revision 和可撤销记录。

### AI 创建临时移动铰链

1. 用户说明希望调整的部件，例如左臂。
2. 模型给出语义部件与连接关系，Host 解析为控制体、连接器和固定锚点。
3. 用户在画布本地实时拖动控制点或连接点；松开后仍保持编辑模式。
4. 预览可临时隐藏铰链与高亮，或显示修改前位置。
5. 确认创建一笔正式事务；取消恢复原图。临时约束随后消失，Undo 可重新进入可恢复编辑状态。

### 自动工程标注（目标）

1. 用户明确调用自动标注能力。
2. 第二层认领当前会话的专业 Workspace；普通附件或普通第一层操作不会触发认领。
3. 第二层 UI 展示分区、候选、覆盖和冲突，并允许用户调整。
4. 第二层通过第一层的 staged Preview 协议替换、评估、确认或放弃候选。
5. 任务完成、取消或失败后，会话仍保持第二层 UI；只有会话销毁或另一个明确专业能力接管才改变归属。
6. 第二层不可用时暂时显示第一层 fallback，但不删除已持久化的会话认领。

## 4. 产品原则

- 一个会话只有一个正式 Drawing 与 revision 链。
- 模型做语义和策略判断，算法做坐标、约束、碰撞与事务计算。
- 用户选择、AI 注意、候选 Preview 和正式标注是不同状态。
- 所有写入必须 revision-bound、可审计、可恢复，失败不产生半成品。
- 功能按需路由，不依赖上传启发式、关键词特判或全局固定提示词。
- 插件只能通过版本化公共协议扩展，不能 deep import 其他插件内部实现。
- 网站与 DSH 共用核心能力，但本地仓库独立，不承诺隐式同步。

## 5. 当前支持范围

当前已实现：

- 第一层 Drawing/Workspace/Viewer 与 DSH Host/Client；
- 本地清洁线稿导入和矢量化；
- Host-owned 语义选择、Preview、评估、提交与 Undo；
- 多部件确定性变换和临时运动铰链；
- 工程标注确定性核心和第二层 Host 工具原型；
- 浏览器本地预览站与 macOS DSH Launcher。

下一阶段计划：

- 版本化 Drawing Surface API；
- 受控 Canvas Layers 与 Interaction Controllers；
- 会话级、粘性的 Workspace contribution 路由；
- staged extension Preview 公共协议；
- 独立构建的第二层 Client UI 与生产标注工作流。

## 6. 非目标

- VectorAI 自建模型代理、云存储或 Express API；
- 仅凭普通图片上传自动判断图纸意图；
- 让模型反复抄写长句柄、完整 Drawing 或精确坐标；
- 用 SVG、PNG 或模型输出替代 Canonical Drawing；
- 第二层直接访问第一层 Store、仓库文件或 DSH 内部布局；
- 针对某张样例图、人体部件或“打招呼”命令编写特例护栏。

## 7. 验收标准

- 安装第一层后，其他用户无需修改 DSH 源码即可获得受支持能力；rc.8 同页布局兼容补丁必须受版本保护且由 Launcher/安装流程明确处理。
- 第一层在无 VectorAI 服务端时可导入、显示、查询、编辑、撤销和导出 Drawing。
- 普通附件与新会话不自动打开 Drawing Workspace。
- 模型只选语义对象，Host 确定性求解坐标和作用范围；错误、过期或越权 Preview 不提交。
- 第二层通过公共契约工作，卸载后不破坏正式 Drawing 或第一层 Viewer。
- 第二层认领后，完成、取消、失败、刷新均保持专业 UI；不可用时安全 fallback。
- 网站、核心包、DSH 产物、Launcher 与关键 E2E 均通过仓库发布检查。
