# 语义片段授权与输入框任务状态设计

**日期：** 2026-08-11

**状态：** 已确认设计方向，待用户审阅设计文档

**适用范围：** Drawing IR 局部空间编辑、区域识别、图元切分、候选验证、Agent 任务交互

## 1. 背景与真实失败证据

用户指令“把图形的右手举起来打招呼”暴露的根本问题不是单次归一化误差，而是当前流程把视觉搜索区域直接当成了几何修改授权。

最近一次失败运行 `run_1a8f55ca-957d-40a6-b970-7ec0c3df1732` 的审计证据如下：

- Planner 给出的粗略目标范围为 `{minX:300,minY:200,maxX:430,maxY:300}`。
- 语义区域模型返回了从头部一直延伸到身体的长多边形，归一化轮廓为：
  `[(0.14,0.14),(0.36,0.14),(0.33,0.57),(0.32,0.75),(0.18,0.73),(0.17,0.61),(0.14,0.61)]`。
- `RegionResolver` 因此选择了 3 个完整节点、9 个穿越节点和 11 个边界锚点，并生成 25 条切分命令。
- 设计阶段把 13 个节点或片段作为目标，以 `[109.95,300.6835]` 为中心旋转 70 度，生成 28 条命令。
- 最终授权包围盒达到 `{minX:-180.2458,minY:147.748,maxX:208.168,maxY:674.191}`，已经接近整张图 `{minX:20.26,minY:36.48,maxX:470.99,maxY:636.29}` 的高度，并越出文档左侧。
- 确定性验证最终以大量 `BOUNDARY_ANCHOR_DISCONNECTED` 和 `UNEXPECTED_DANGLING_ENDPOINT` 拒绝候选，没有错误提交，但用户已经在临时预览中看到头部等非目标内容被破坏。

当前架构中的具体缺口是：

1. 语义区域输出同时承担“给模型看哪里”和“允许模型改什么”两种职责。
2. 任何位于区域内或穿越区域的图元都会自动进入目标集合，没有独立的语义归属确认。
3. 同一个 polyline 中的手臂和身体即使只需修改局部，也会因源图元相同而被共同授权。
4. 两个图元只是在视觉上重叠时，当前候选生成容易把它们当成同一修改对象。
5. 过大的区域、过多的片段和过多的锚点没有在进入设计阶段前被确定性拒绝。
6. 前端任务面板占据独立区域，状态和输入动作分离，不符合用户希望的 Codex 式紧凑交互。

## 2. 设计结论

局部编辑流程改为四个彼此分离的概念：

1. **Search Envelope（搜索包络）**：模型认为目标大致位于哪里，只决定接下来提取哪些局部上下文。
2. **Atomic Candidates（原子候选）**：后端在搜索包络内确定性生成可单独授权的线、圆弧、曲线片段和关系候选。
3. **Selection Proof（选择证明）**：后端渲染带稳定编号和颜色的候选图，模型必须明确指出哪些原子片段属于用户目标，并给出简短证据。
4. **Fragment Authorization（片段授权）**：只有经过验证的明确片段集合可以变化；其余内容无论是否位于搜索包络内、是否与目标重叠，全部属于保护集合。

因此，“圈中了什么”不再等价于“会修改什么”。区域只用于缩小观察上下文，真正的修改权由片段级授权决定。

## 3. 目标

- 把“局部语义理解”与“几何写权限”分离。
- 支持在同一源图元中只修改一个局部片段。
- 支持视觉上重叠但语义不同的图元保持独立。
- 默认保持目标之外的几何、样式、拓扑和标注完全不变。
- 在设计前拒绝明显过大的搜索或选择，避免生成破坏性预览。
- 保留模型对整张图的完全控制能力，但所有控制都必须显式转化为可审计的 Drawing IR 增量事务。
- 让失败后的重新定位、重新选择、重新设计均有明确的反馈 Loop 和可回归记录。
- 将任务状态吸附在聊天输入框上方，并让发送按钮根据任务状态承担发送、暂停、继续和重试动作。

## 4. 非目标

- 本次不引入通用图像分割大模型或完整 CAD 约束求解器。
- 本次不要求一次选择就永久正确；选择错误可以通过证据反馈重新选择。
- 本次不允许模型使用整张栅格预览绕过 Drawing IR 直接覆盖图纸。
- 本次不为旧的“区域即授权”路径保留兼容分支。项目仍处于 MVP，迁移完成后直接删除旧主路径。
- 本次不把内部模型名称显示给用户。

## 5. 核心数据模型

### 5.1 SearchEnvelope

```ts
interface SearchEnvelope {
  id: string;
  revision: number;
  polygon: Point[];
  semanticLabel: string;
  confidence: number;
  source: 'planner-hint' | 'vision-grounding' | 'repair';
  targetHint?: TargetHint;
}
```

它只能授权读取和候选提取，不能授权 Drawing IR 写操作。

### 5.2 TargetHint 与 LocalityBudget

```ts
interface TargetHint {
  semanticDescription: string;
  approximateBounds?: Bounds;
  preferredScale?: 'detail' | 'part' | 'assembly' | 'drawing';
  expectedKinds?: DrawingNodeKind[];
}

interface LocalityBudget {
  maxAreaRatio: number;
  maxSpanRatio: number;
  maxWholeNodes: number;
  maxCrossingNodes: number;
  maxBoundaryAnchors: number;
  maxCandidateFragments: number;
}
```

预算由意图尺度和文档统计确定。它不是固定像素阈值，也不能简单依赖左右位置：角色的“右手”可能位于画面左侧，屏幕方向和解剖方向存在歧义。系统主要通过区域尺度、候选数量、与粗略提示的相对距离及语义证据判断异常。

### 5.3 AtomicCandidate

```ts
interface AtomicCandidate {
  fragmentId: string;
  sourceNodeId: string;
  lineage: string[];
  kind: DrawingNodeKind;
  geometry: DrawingGeometry;
  localBounds: Bounds;
  endpointIds: string[];
  relationIds: string[];
  virtualSplit?: {
    startParameter: number;
    endParameter: number;
  };
  baselineHash: string;
}
```

`fragmentId` 在同一 Drawing IR revision 和同一切分参数下稳定。虚拟切分在选择阶段不修改规范文档；只有选择通过后才物化成事务命令。

### 5.4 SelectionProof

```ts
interface SelectionProof {
  envelopeId: string;
  revision: number;
  proofViewId: string;
  editableFragmentIds: string[];
  protectedFragmentIds: string[];
  anchorIds: string[];
  evidence: Array<{
    fragmentId: string;
    reason: string;
    confidence: number;
  }>;
}
```

后端生成 `proofViewId` 对应的候选证明图：每个原子片段使用稳定编号、可区分颜色和局部上下文显示。模型只能从服务端给出的 ID 集合中选择，不能虚构 ID，也不能用“区域内全部内容”代替明确列表。

### 5.5 FragmentAuthorization

```ts
interface FragmentAuthorization {
  authorizationId: string;
  revision: number;
  editableFragmentIds: string[];
  protectedFragmentIds: string[];
  boundaryAnchorIds: string[];
  selectionProofId: string;
  protectedHashes: Record<string, string>;
  localityMetrics: LocalityMetrics;
}
```

编译器只接受 `editableFragmentIds`。任何未列入 editable 集合的节点或片段默认受保护，无需显式穷举整个文档。

## 6. 新的局部编辑流程

### 6.1 阶段一：粗定位

Planner 根据用户意图、当前视觉图和必要的 Drawing IR 摘要生成 `TargetHint`。语义区域模型基于目标提示输出 `SearchEnvelope`。

该阶段允许有一定冗余，目的是避免漏掉目标的连接上下文；但冗余不能直接扩大写权限。

### 6.2 阶段二：包络确定性校验

后端在任何切分或设计调用之前计算：

- 包络面积占文档面积比例；
- 包络宽高跨度占文档跨度比例；
- 完整包含、穿越和邻近节点数量；
- 预计虚拟切分数量；
- 边界连接锚点数量；
- 与 `TargetHint` 尺度和位置的相对偏差。

超过 `LocalityBudget` 时立即拒绝，并把具体缺陷反馈给区域模型，例如：

```text
目标是单个手臂，但当前区域覆盖文档高度的 84%、包含 12 个候选节点和 11 个边界锚点。
请仅覆盖手臂轮廓及其与身体连接处的最小邻域，不要包含头部或躯干主体。
```

左右位置只作为弱证据，不能单独导致拒绝。

### 6.3 阶段三：构建原子候选图

`AtomicCandidateBuilder` 在搜索包络及一个可控的上下文边距内工作：

1. 完整独立图元直接成为候选。
2. 穿越包络或语义边界的 polyline、spline、arc 生成虚拟片段。
3. 片段保留源节点 lineage、几何参数区间、端点和关系信息。
4. 端点极近的无意义短片段按文档容差吸附或合并。
5. 文字、尺寸标注默认只作为上下文，不进入可编辑候选；用户明确要求修改标注时才开放。

候选图中的“连接”必须来自 Drawing IR 显式关系、共享稳定端点或容差内确认的拓扑节点。仅仅在栅格预览上相交，不自动创建拓扑关系。

### 6.4 阶段四：生成选择证明视图

后端使用与前端一致的 Drawing IR 渲染器生成局部证明图：

- 每个候选片段有稳定短编号；
- 相邻候选使用清晰但克制的颜色区分；
- 原图上下文以低对比度显示；
- 端点、共享关系和边界锚点可单独标识；
- 证明图记录 revision、视口矩阵和候选 ID 映射，可离线重放。

模型同时收到候选的紧凑向量摘要和证明图，返回精确的 `editableFragmentIds`、需要保持的锚点以及逐片段选择理由。

### 6.5 阶段五：验证选择

`SelectionVerifier` 在设计前执行以下检查：

- 所有 ID 存在且属于当前 revision 的候选集合；
- editable 集合非空，数量不超过预算；
- 选择包围盒、总曲线长度和片段数量符合意图尺度；
- 必需连接锚点已包含，且未把无关大部件加入 editable 集合；
- 同一源图元的未选片段明确进入保护基线；
- 重叠图元保持各自独立 ID，未选择的一方继续受保护；
- 选择理由与候选类型、位置和邻接关系基本一致。

失败时返回结构化缺陷并重新选择；只有证据表明 SearchEnvelope 本身缺失目标或严重错误时才重新定位。

### 6.6 阶段六：物化授权并设计

选择通过后才把所需虚拟切分物化为 Drawing IR 临时事务，并生成 `FragmentAuthorization`。设计模型收到：

- 用户意图；
- editable 片段的完整向量数据；
- protected 邻域的只读向量摘要；
- 边界锚点和显式关系；
- 局部视觉预览；
- 默认不变量：保持连接、其他部分完全不变、尽量最小修改。

编译器拒绝任何引用授权集合外节点或片段的命令。候选预览、确定性验证、视觉复核和修复 Loop 继续沿用 Drawing IR 增量事务机制。

## 7. 重叠、相交和同源图元规则

### 7.1 独立重叠图元

两个图元即使在屏幕上完全重叠，只要 `sourceNodeId`、lineage 或显式关系不同，就仍是两个独立候选。模型选择其中一个不会授权另一个。

被选择图元改变后，如果暴露出原先遮挡的图元，这是正确的几何结果，不应自动删除或同步修改被遮挡图元。

### 7.2 视觉相交不等于拓扑连接

线段在二维投影上相交时，只有满足以下条件之一才视为连接：

- Drawing IR 存在显式连接关系；
- 两个图元共享同一个稳定端点 ID；
- 导入阶段已在容差内建立并审计过拓扑节点。

否则相交点只作为视觉上下文，不产生共同移动或共同授权。

### 7.3 同一 polyline 或 spline 内的局部目标

当手臂与身体轮廓来自同一个源图元时，系统按语义边界和拓扑锚点建立虚拟切分：

- 仅手臂参数区间进入 editable 集合；
- 身体参数区间进入 protected 集合；
- 两端连接点成为边界锚点；
- 修改后重新组装或保留为有 lineage 的多个合法 Drawing IR 图元；
- 保护片段的规范化哈希必须保持不变。

这使语义选择可以小于 CAD 图元粒度，同时仍保留可审计和可撤销的事务边界。

## 8. 失败分类与反馈 Loop

| 失败阶段 | 典型问题 | 下一步 | 复用内容 |
| --- | --- | --- | --- |
| SearchEnvelope | 区域过大、漏掉目标、尺度明显错误 | 重新定位 | TargetHint、失败指标 |
| Atomic Candidates | 候选过多、切分不稳定、短片段爆炸 | 调整容差或缩小包络 | 已验证包络、节点索引 |
| Selection Proof | 选错部件、混入重叠对象、漏掉锚点 | 重新选择 | 包络、候选图、证明视图 |
| Design | 目标姿态错误、形变不自然 | 重新设计 | 授权、锚点、保护哈希 |
| Compile/Validate | 越权命令、断开连接、保护内容变化 | 修复设计或确定性编译 | 完整授权与失败差异 |
| Visual Review | 结构语义仍不符合原图或用户意图 | 带前后预览重新规划 | Episode 全上下文 |

任何阶段失败都必须明确失效边界。设计失败不能重新扩大选择；选择失败不能自动修改几何；区域失败不能进入切分和预览。

第 1、2 个逻辑候选继续使用轻量模型，第 3 个逻辑候选升级到高能力模型。模型是可替换执行器，授权、验证、审计和回归协议不依赖具体模型名称。

## 9. UI：吸附在输入框上的真实任务状态

独立的 `ConstructionTimeline` 大卡片替换为紧贴输入框上方的 `ComposerTaskStatus`。它位于聊天底部固定区内，与输入框形成一个视觉整体，只显示最新的真实业务状态和必要的次级信息。

推荐结构：

```text
正在确认右手的 4 个轮廓片段                  00:18  ·  停止
┌────────────────────────────────────────────────────────┐
│ 追加指令…                                         [暂停] │
└────────────────────────────────────────────────────────┘
```

状态文案来自真实领域事件，例如：

- 正在定位需要修改的右手；
- 找到 14 个局部片段，正在确认目标；
- 已选中 4 个手臂片段，正在保持 2 个连接点；
- 正在生成局部候选；
- 检测到 1 个连接断开，正在修复；
- 候选已通过验证，正在提交。

不显示固定阶段列表，不显示模型名称。完整事件仍写入 Episode 和审计记录。

### 9.1 主按钮状态机

| 任务状态 | 输入为空 | 输入非空 |
| --- | --- | --- |
| idle / completed / stopped | 发送禁用 | 发送新任务 |
| planning / running / validating | 暂停 | 发送追加指令 |
| pause_requested | 显示等待状态并禁用重复点击 | 发送追加指令，指令进入当前 Episode |
| paused | 继续 | 发送追加指令，保持暂停，用户可随后继续 |
| retryable_error | 重试原任务 | 发送新任务 |
| terminal_error | 重试并显示准确原因 | 发送新任务 |

行为约束：

- 任务运行且输入为空时，原发送按钮位置直接变成暂停按钮。
- 用户开始输入后，同一个按钮立即恢复为发送追加指令；不额外占用输入框空间。
- 暂停后输入为空时显示继续；输入新指令时先记录到当前 Episode，任务仍保持暂停，避免用户尚未确认就自动执行。
- 失败且输入为空时显示重试，重试基于最新规范 Drawing IR 创建新 runId；输入非空时视为新的用户任务。
- 停止作为状态条中的小型次级操作保留，不与高频主动作竞争。
- 清除和其他终态操作只在任务终止后出现，不进入主按钮状态机。

### 9.2 状态更新规则

- 领域事件优先于通用模型事件和心跳。
- 心跳只更新用时，不覆盖“正在确认片段”等真实动作。
- 状态条只显示最新状态；失败原因可展开，但默认保持一行或两行。
- 超过 30 秒不是失败条件。状态条继续显示当前动作和用时，并提示“这一步需要更长时间”。
- 页面刷新后从当前 Episode 恢复任务状态，不能退回固定假进度。

## 10. 审计与可回归性

每轮局部编辑至少记录：

- 原始用户意图和自动附加的不变量；
- `TargetHint`、`SearchEnvelope` 和 locality 指标；
- 原子候选集合、稳定 ID、lineage 和 proof view；
- 模型返回的选择证据；
- `FragmentAuthorization`、editable/protected 集合及保护哈希；
- 所有候选事务、预览摘要、验证问题和修复分类；
- 用户暂停、追加指令、继续、停止和重试事件；
- 每阶段耗时、模型层级和最终提交 revision。

回归运行可以固定模型结构化输出，离线重放包络校验、候选生成、选择校验、事务编译和差分验证，不需要重复调用外部模型。

## 11. 验收与回归门槛

### 11.1 后端单元测试

- 大范围语义包络超过单部件预算时，在任何切分和设计调用前被拒绝。
- 包络可包含两个重叠图元，但只授权被明确选择的一个；另一个规范化哈希保持不变。
- 同一 polyline 中的手臂和身体被虚拟切分后，只允许修改手臂参数区间。
- 视觉相交但无显式关系的图元不会自动生成共同锚点。
- 模型返回未知片段 ID、空选择或过多片段时选择校验失败。
- 编译器引用授权外节点时返回明确的越权错误。
- protected 集合的几何、样式、语义和 lineage 哈希在候选前后保持一致。
- 选择稳定后，设计修复轮次复用原授权，不重新执行区域识别。

### 11.2 真实失败回归

用 `run_1a8f55ca-957d-40a6-b970-7ec0c3df1732` 的归一化轮廓和 Drawing IR fixture 建立回归：

1. 该长包络必须在设计前被判定为过大，不能生成 25 条切分命令和破坏性预览。
2. 缩小后的候选证明图应把手臂、身体、头部和重叠轮廓作为独立片段呈现。
3. 选择右臂后，头部和躯干主体的保护哈希保持不变。
4. 候选必须保持手臂与身体的原有连接；失败时进入设计修复，不扩大授权范围。

### 11.3 前端组件测试

- 状态条位于 composer 内并紧贴输入框上方，独立任务大卡不再渲染。
- 运行中空输入显示暂停，输入文字后显示发送追加指令。
- paused 空输入显示继续，paused 非空输入发送指令但不自动继续。
- retryable error 空输入显示重试，非空输入创建新任务。
- 最新领域事件不会被心跳或通用模型事件覆盖。
- 内部模型名称不会出现在任务状态中。

### 11.4 集成与视觉验收

- 使用 test2 干净线稿执行“把图形的右手抬起来打招呼”。
- 从定位、候选选择、设计、验证到提交均显示真实最新状态。
- 临时候选只改变右臂，不破坏头部、躯干或另一只手。
- 与身体连接未通过验证时不允许提交；失败候选不会残留在规范 Drawing IR。
- 用户可在运行中暂停、追加“手臂再高一点”、继续，并基于同一 Episode 上下文重新规划。
- test1/test2 的导入、矢量化、自动标注、显示隐藏和已有 Drawing IR 渲染行为不退化。

## 12. 迁移策略

本次按 MVP 直接替换主路径：

1. 将现有语义 region 输出重命名并限制为 `SearchEnvelope`。
2. 把当前 `RegionResolver` 拆成包络测量、原子候选构建、选择验证和授权物化四个职责。
3. 在 semantic adapters 中增加目标提示、候选证明和选择证明协议。
4. 编译器改为强制接收 `FragmentAuthorization`，删除“区域内节点自动可改”的入口。
5. 运行时加入 envelope/selection/design 三个独立修复边界和真实事件。
6. 前端用 `ComposerTaskStatus` 替代独立 `ConstructionTimeline` 展示，但保留审计事件存储。
7. 删除旧的直接区域授权和固定阶段 UI 兼容逻辑，不维护双路径。

Drawing IR、增量事务、前后端同源渲染、候选预览、确定性验证和 Episode 审计继续作为系统基础，不进行第二套数据模型迁移。

## 13. 最终原则

AI 可以看得宽，但只能改得准。

视觉区域负责提供上下文，选择证明负责建立语义归属，片段授权负责限定写权限，Drawing IR 事务负责执行与回放，确定性验证负责守住未选内容和连接拓扑。这样既不把 AI 限制在粗糙的 CAD 图元边界内，也不会因为模型圈选稍大就让整个重叠区域一起被修改。
