# 确定性自动标注设计

日期：2026-08-16

## 1. 目标

第一版以“初始 DXF + 工程文档”为唯一运行时输入，自动生成能够被 Drawing IR 理解、隐藏、审计和撤销的正式标注。

`样本图001.dxf` 只用于建立验收真值，不作为运行时输入，也不要求系统兼容其中被压平为匿名 BLOCK/INSERT 的 CAXA 标注表达。

第一版只生成可以被初始几何或工程文档完全证明的内容。任何无法证明的设计意图不得猜测、不得以占位符提交。

## 2. 权威来源

按以下优先级解释事实：

1. 初始 DXF 是几何、坐标、单位和拓扑的权威来源；
2. 工程文档是区域名称、目标位置、宽度、外径及后续显式工程要求的权威来源；
3. 样本 DXF 提取结果是测试 Oracle，只用于判断系统是否漏标、错标，不参与生产规划；
4. 模型推理、行业默认值和样本特例都不能将未知事实升级为已确认标注。

当工程文档与几何冲突时，系统保存冲突诊断，不生成该项标注。当前样本中的花键文档外径 `45` 与几何/样本尺寸约 `44.59` 不一致，应进入冲突清单。

## 3. 第一版范围

### 3.1 可以生成

- 由明确几何端点或轮廓段确定的线性、对齐尺寸；
- 由旋转轴和轮廓确定的直径尺寸；
- 由显式圆弧确定的半径尺寸；
- 由明确相交方向确定的角度尺寸；
- 由明确倒角几何确定的倒角引线；
- 由对称轮廓或显式轴线确定的中心线；
- 工程文档中与几何核验一致的区域宽度、位置和外径；
- 工程文档明确给出的普通说明文字。

公称尺寸与公差是相互独立的事实。公称值可证明但公差未知时，只生成公称尺寸，不补写公差。

### 3.2 暂不生成

- 未在文档中给出的尺寸公差和配合；
- 表面粗糙度；
- 基准及基准字母；
- 形状和位置公差框；
- 截面位置、方向和编号；
- 材料、热处理、加工和检验要求；
- 仅能从样本匿名块或 CAXA 私有数据猜出的语义。

这些项目进入结构化 `pendingAnnotations`，包含缺失原因和需要用户补充的字段，但不会显示成画布标注。

## 4. Annotation IR

所有自动生成内容必须位于 Annotation plane，不能用普通 GeometryNode 拼装标注外观。

第一版使用以下语义类型：

- `dimension`：linear、aligned、diameter、radius、angular；
- `leader`：倒角、半径或明确文字说明的引线；
- `centerline`：轴线及中心标记；
- `text`：工程文档明确给出的说明。

每个标注保存：

- 稳定 ID；
- 标注种类和数值；
- 精确几何目标与锚点；
- 来源 Evidence；
- 单位和显示格式；
- `confirmed` 质量状态；
- 布局锚点、方向和避让结果。

后续公差、粗糙度、基准、形位公差和截面标识会扩展为独立 Annotation 类型，不复用普通文字或几何图元。

## 5. 确定性测量

测量器从初始图生成 `MeasurementFact`：

- 主轴和左右端；
- 轴向轮廓断点与相邻轴段；
- 每个轴段的直径、中心位置和宽度；
- 肩部、槽、圆弧、圆角、倒角和相交方向；
- 显式中心线和对称证据；
- 工程区域与轮廓段的唯一匹配。

每个 Fact 必须带来源实体、计算方法、数值误差和稳定锚点。无法唯一匹配时返回 candidate/conflict，不进入标注规划器。

## 6. 标注规划与布局

规划器只消费 confirmed MeasurementFact 和已核验工程字段：

1. 根据通用轴类零件规则选择需要表达的公称尺寸；
2. 使用稳定 `factKey` 去重；
3. 生成 Annotation IR，不生成视觉线段；
4. 布局器在图形上下方建立确定性标注通道，按包含关系和跨度分层；
5. 直径标注靠近对应轴段，线性尺寸按局部、区域、总体从近到远排列；
6. 引线避开主体轮廓和已有文字；
7. 同样输入必须得到相同位置和顺序。

### 6.1 轴向尺寸链规则（按工业图纸惯例）

- 同一条轴向尺寸链默认按“链式标注”处理：输出“整体/起止端”长度的主导尺寸，同时对同一链中间非端点长度保留一条作为留白（容差窗口）。
- 同一链若出现高规则化的重复特征（齿槽、齿链、均匀台阶）或与关键几何实体（圆、弧、椭圆、样条）高度相关，则保留全链，不做省略。
- 省略规则以“工程实用可读性”优先：不遗漏已确认关键边界尺寸，且每个被省略的尺寸在 `suppressionReasons` 里保留可审计说明。

布局失败不会删除标注事实，而是返回可审计诊断并阻止不完整事务提交。

## 7. 完整性闭环

自动标注结果必须通过 `AnnotationCoverageReport`：

- 每个 confirmed Fact 必须被一个标注消费，或有明确的“不需要显示”规则；
- 每个生成标注必须引用存在的 Fact 和几何目标；
- 不允许重复数值、悬空锚点和超出图框的文字；
- pending/conflict 不得出现在正式标注数组；
- 所有标注必须能被统一隐藏且不能作为普通几何选中；
- 整批标注通过一笔 Drawing Transaction 提交，失败不产生半成品。

## 8. 样本验收

从已经提取的样本标注建立测试 Oracle，并逐项分类：

- `derivable`：初始几何可证明；
- `document-confirmed`：文档给出且与几何一致；
- `pending`：需要公差、粗糙度、基准、形位公差、截面定义等设计输入；
- `conflict`：文档与几何不一致。

回归测试只要求第一版生成前两类。必须证明：

- 初始 DXF 不携带样本标注仍能生成相同的确定性公称标注；
- `pending/conflict` 为零误提交；
- 确定性标注无遗漏、无重复、无普通 GeometryNode 污染；
- 隐藏/显示、Undo、重放和浏览器渲染一致；
- 全流程不调用模型，并保持在交互可接受的时间内。

## 9. 数据流

```text
初始 DXF
  → Lossless Manifest / Drawing IR Geometry
  → Deterministic Measurement Facts
  → Engineering Document Reconciliation
  → Confirmed Facts + Pending/Conflict
  → Annotation Planner
  → Deterministic Layout
  → Coverage Validator
  → Annotation Transaction
  → Shared Scene Renderer
```

## 10. 非目标

- 第一版不自动猜测制造公差或行业工艺；
- 不为复刻样本位置写固定坐标或对象名称规则；
- 不把匿名块的线条直接复制成正式标注；
- 不以 AI 视觉模型替代确定性几何测量；
- 不要求第一版解释所有 CAXA 私有标注语义。
