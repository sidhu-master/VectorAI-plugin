# CAD 排版与导出重构

## 用户要求与真实验收路径

用户要求重构排版器和导出器，使工程图达到提供的黄金样本效果，并逐项核对，不以外观接近或测试数量作为通过依据。

验收路径：导入原始 DXF 和工程区域文档 → 生成几何尺寸与尺寸方案 → 通过现有工程标注输入/确认流程施加参考图中明确给出的设计要求 → 持久化 Drawing 与方案 → 从产品使用的导出函数生成 DXF → 独立解析逐项报告 → 同尺度渲染核对。数值、目标绑定、布局和 CAD 表达分别验收。测试不得再用前两条任意 LINE 伪造基准，也不得把“待计算”当作目标公差通过。

提供的目标 DXF/截图是本次验收设计要求的来源。原始 INI 没有给出的公差、粗糙度等，可以记录在测试专用的明确要求文件中，经真实领域 API 应用。生产代码不得读取目标 DXF、识别样本 ID/哈希/名称或包含样本坐标、固定尺寸集合。

## 保持的行为

- 不改变源几何、原始测量值、目标关联或用户显式尺寸文字来获得视觉相似。
- 导出当前可见草稿，草稿不存在时使用已确认版本；保留显隐、图层、原始 HATCH 和可移植公差。
- 手动位置、手动尺寸链偏移以及撤销/重做、保存/恢复有效。
- 导出是纯投影，不修改持久化 Drawing 或方案，不在导出中再次调用识别器猜测自动位置。
- 通用圆孔、平板、旋转尺寸同样有效；轴类黄金样本只是验收案例之一。
- 不增加状态 UI，不修改模型意图路由，不引入生产 Python 依赖，不发布包。

## 明确改变的行为

- 新生成的尺寸有明确的自动布局所有权。只有 `layout.mode = automatic` 可以在导出时重新安排纸面位置；旧记录无此字段时保守保留。
- 手动移动尺寸/文字后转为 manual；撤销恢复原所有权与位置，再次标注不得覆盖 manual/旧记录位置。
- CAD 纸面投影统一计算字体/公差包围盒、文字间隙、尺寸分层、端部角度和半径放置。
- 参考工程外观中的角度文字采用横排；由可选 profile 策略控制，并写入原生文字转角与尺寸图片。未指定该策略的通用 profile 保留原有沿角弧方向。
- 真正的圆直径保留原生 diametric；剖视轮廓之间的直径使用带直径前缀的线性 CAD 表达，领域尺寸仍然是 diameter。此项替代旧技术文档将所有 diameter 一律输出 diametric 的做法。
- 工程符号使用统一的纸面比例与分组布局，自动符号围绕实际受控目标安放；显式 framePosition/labelPosition 保留其锚点语义。
- CAXA 粗糙度样式独立规定短臂、长臂、60°夹角及文字间隙，并按文字高度缩放；不将该供应商纸面样式冒称为强制国标。未配置该样式的 profile 保留原轮廓。
- 实际见证 LINE 采用 profile 的颜色，普通 TEXT 写入实体字宽，避免样式表与缓存图元不一致。自动尺寸同时检查箭头三角形与固定文字；空间允许时使用内置箭头和对应的原生局部间隙覆盖，不裁坏箭头或移动测量端点。
- Writer 只消耗确定的纸面坐标和样式，保证文字、尺寸线、箭头及原生 DIMENSION 的几何一致。已有句柄、角度字段和公差词法修复必须保留。

## 分层与边界

1. `drawing-core` / `plugin-space-contracts`：通用尺寸布局所有权，严格持久化契约；通用 DXF 实体和文字/箭头图元生成。
2. `drawing-edit-core` / `plugin-dsh-space-host`：人工移动与 undo/redo 的所有权转换。
3. `engineering-annotation`：生成自动尺寸和明确工程语义，保留已有人工布局；不负责供应商字体。
4. `plugin-dsh-annotation-host/cad-dimension-layout`：纯纸面尺寸投影，计算实际文字及公差占位，确定可读位置和分层。
5. 工程符号投影与工程导出编排：确定基准/GD&T/粗糙度框的目标、分组、引线和位置，组合可审计的导出场景。
6. 测试专用 Oracle：目标文件逐实体清单与独立检查器，与生产运行时隔离。

## 逐项验收

目标清单初步包括 28 个尺寸、18 个符号 INSERT、9 个参考注记；数量仅用于发现漏项，不能作为通过条件。

每个尺寸核对：角色、名义显示与原始测量、上下偏差/公差形式、关联表面或端点、原生实体种类、尺寸线所在侧与层级、文字方向/字号/宽度/间隙、箭头尖端及方向、见证线间距与超出量、可编辑 DIMENSION 重生结果。

每个符号核对：A/B 与哪一个实际表面绑定；各 GD&T 行的特征、值、基准组合与受控对象；粗糙度数值、材料去除符号与所指表面；工艺注记和参考标识的内容、引线和关联位置。

整图核对：源几何一致，HATCH 边界和图案一致，层/色/线宽/字体一致，没有文字被尺寸线或引线穿过，没有不应出现的闭合尺寸；变换后的非样本输入仍满足相同规则。

报告逐项标记 pass / fail / unsupported。缺项和 unsupported 都不计通过。CAD 字体不可用时明确记录渲染限制，不以替代字体的近似图证明字体通过。

复查补充：原严格检查器将 DIMENSION 匿名块中的 BYBLOCK 颜色错误地继承为尺寸层颜色，粗糙度轮廓也仅在严格图元差异中检查。补充独立渲染颜色和符号实测审核，保留原清单及差异，不让这两项漏判继续作为通过依据。ezdxf 重新渲染不自动采用原生用户文字位置，数值／公差与箭头重生成可单独验证，真实 CAD 文字保位仍需目标环境检查。

## 实施顺序

先建立 Oracle 与失败基线；同时补布局所有权。然后完成纸面尺寸及符号的投影并接入真实导出入口，以明确要求驱动真实验收输入。最后逐项消除报告中的失败，验证人工布局生命周期与普通二维图，重建两个本地插件并确认产物新鲜度。

原有 2026-08-31 设计中的“允许内容不同”不能用于免除本次显式要求清单中的检查；缺少设计要求的普通用户输入仍须按产品原有证据规则处理。
